## STRIDE Threat Analysis Table

| Flow# | S – Spoofing | T – Tampering | R – Repudiation | I – Info Disclosure | D – Denial of Service | E – Elevation of Privilege |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **F1** | **Yes** – stolen credentials can impersonate a legitimate user. | **Yes** – attacker-controlled input can alter the request or backend query. | **Yes** – weak logging makes login actions hard to trace. | **Yes** – error messages may leak account existence. | **Yes** – repeated login requests exhaust server resources. | **Yes** – SQL injection may bypass authentication or alter role logic. |
| **F2** | **Yes** – a stolen session can impersonate the student. | **Yes** – parameters can be tampered to query other users' data. | **Yes** – no access logs mean the user can deny viewing the page. | **Yes** – authorization flaws could expose other students' grades. | **Yes** – repeated requests consume application resources. | **No** – viewing others' data is horizontal overreach, not vertical privilege elevation. |
| **F3** | **No** – server responses do not initiate identity spoofing. | **Yes** – a man-in-the-middle can tamper with returned grade data. | **No** – the response itself is not an audit record. | **Yes** – grades and comments are private student data. | **Yes** – blocking responses can prevent students from accessing the service. | **No** – returning data cannot elevate user permissions. |
| **F4** | **Yes** – stolen teacher credentials can impersonate a teacher. | **Yes** – grade/comment fields are attacker-controlled. | **Yes** – insufficient logging makes grade changes hard to prove. | **Yes** – requests contain private student information. | **Yes** – repeated writes exhaust server resources. | **Yes** – bypassed authorization allows unauthorized users to modify grades. |
| **F5** | **No** – server responses do not initiate spoofing. | **Yes** – a man-in-the-middle can alter returned grade data. | **No** – the response itself is not an audit record. | **Yes** – private student grades are disclosed. | **Yes** – disrupting responses can prevent teachers from using the service. | **No** – data return does not grant higher permissions. |
| **F6** | **Yes** – stolen admin credentials can impersonate an administrator. | **Yes** – user/class fields can be tampered to change actions. | **Yes** – weak audit records make admin actions disputable. | **Yes** – requests may contain personal information. | **Yes** – repeated admin requests exhaust resources. | **Yes** – if authorization is missing or bypassed, a lower-privileged user could access admin functions. |
| **F7** | **No** – server responses do not initiate spoofing. | **Yes** – returned admin data can be tampered with in transit. | **No** – the response itself is not an audit record. | **Yes** – user and class information can be sensitive. | **Yes** – blocking responses can prevent administrators from accessing the service. | **No** – returning data cannot elevate permissions. |
| **F8** | **Yes** – an attacker can spoof application identity to run unauthorized SQL. | **Yes** – SQL writes can modify grades or user data. | **Yes** – weak database logs make changes harder to trace. | **Yes** – queries may access private application data. | **Yes** – expensive queries can overload the database. | **Yes** – SQL injection or excessive DB privileges can grant unauthorized database-level capabilities. |
| **F9** | **No** – the database does not act as a human identity. | **Yes** – database data can be altered before the application uses it. | **No** – data return does not involve user repudiation of actions. | **Yes** – results can contain private grades or user data. | **Yes** – database overload prevents results from returning. | **Yes** – manipulated results can trick the application into trusting unauthorized data. |
